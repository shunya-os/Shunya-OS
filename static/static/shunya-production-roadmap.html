3. Build Phases

Each phase produces a user-visible milestone. No phase produces only infrastructure — every phase ends with something a founder can touch.

Phase 1: Pipeline Activation essential

2 weeks · Workstream A · 2 engineers
What a founder can do after this phase:
Sign up, log in, see Executive Home with real data. AI can observe their actions and begin building context.
  • Wire Cognitive Runtime (8 intelligence engines) into OS pipeline
  • Wire Execution Runtime into OS pipeline
  • Wire Planning Runtime into OS pipeline
  • Replace all 8 mock runtimes with real implementations
  • Verify pipeline end-to-end: intent → pipeline → intelligence → execution → workspace update
  • Acceptance: `process_intent()` flows through all 11 stages with real engines, not mocks

Phase 2: Entity System Launch essential

3 weeks · Workstream B · 1 engineer
What a founder can do after this phase:
Create any business object (lead, contact, deal, invoice) without schema changes. See them in table, kanban, or calendar views.
  • Build entity_definitions CRUD (JSONB schema per tenant)
  • Build entities CRUD (generic data storage)
  • Build entity_list view with configurable columns
  • Build entity_detail view with dynamic schema rendering
  • Build entity_form auto-generated from schema
  • Build kanban pipeline view for any entity type
  • Add search indexing for entity data fields
  • Acceptance: Admin can define a "Patient" type with 20 custom fields and start creating patients

Phase 3: AI Copilot essential

3 weeks · Workstream C · 1 engineer
What a founder can do after this phase:
Ask SHUNYA questions about their business in natural language. Get AI-generated summaries of entities, conversations, and commitments.
  • Build LLM provider abstraction layer (provider-agnostic)
  • Build AI Copilot component — persistent chat sidebar
  • Connect Copilot to Cognitive Runtime for context-aware answers
  • Build AI-summary generation for any entity
  • Build conversation workspace with linked objects
  • Acceptance: Founder asks "What's the status of the Smith deal?" and gets a real AI-generated response from their data

Phase 4: Executive Home & Commitments essential

2 weeks · Workstream A+B combined · 1-2 engineers
What a founder can do after this phase:
See their entire business at a glance — key metrics, open commitments, next actions, AI-generated daily brief.
  • Build Executive Home dashboard with real metrics
  • Build Commitment Tracker with progress bars and confidence meters
  • Build AI daily brief component
  • Connect commitments to Decision Engine
  • Build next-action recommendations from Planning Engine
  • Acceptance: Founder can log in, see 3 metrics, 5 commitments, and an AI brief that references their actual data

Phase 5: Integrations & Notifications required

3 weeks · Workstream D · 1 engineer
What a founder can do after this phase:
Connect their email and calendar. Receive notifications when things change. Import existing data from other tools.
  • Build email connector (IMAP sync, SMTP send)
  • Build calendar connector
  • Build in-app notification system
  • Build email notification dispatch
  • Build data import pipeline (CSV, contacts)
  • Acceptance: Founder connects Gmail, sees emails linked to entities, gets notified of entity updates

Phase 6: Automation & Workflows required

3 weeks · Workstream A+B · 1 engineer
What a founder can do after this phase:
Create "when X happens, do Y" rules. Delegate work automatically. Track SLA breaches.
  • Wire Automation Runtime into OS pipeline
  • Build rule engine UI (when/if → then/do)
  • Build workflow templates library
  • Connect automation to Decision Engine for governance approval
  • Acceptance: Founder creates "when lead status = booked, send welcome email and create task" — it fires automatically

Phase 7: Founders Complete essential

2 weeks · All workstreams · 2 engineers
What a founder can do after this phase:
Everything the founder needs to run their business: manage customers, track deals, communicate with team, get AI insights, automate workflows — all in one OS.
  • Universal Search (⌘K) finalized
  • Keyboard navigation audit (tab, escape, enter everywhere)
  • Object relationship navigation (click through linked objects)
  • Empty states everywhere — no lorem ipsum, no fake data
  • CI/CD pipeline operational
  • Backup & recovery verified
  • End-to-end founder journey test passes

Phase 8: Private Beta Launch required

1 week · All · 2 engineers
What a founder can do after this phase:
SHUNYA is live at shunyaos.com. A first customer can sign up and run their business.
  • Security review (auth, data isolation, credential storage)
  • Load testing (50 concurrent users)
  • Error monitoring (Sentry or equivalent)
  • Onboarding flow — first-run experience for new founders
  • Launch checklist sign-off

Phase 9+: V1.x long-term

Ongoing
Mobile app, Client Portal, Payments, i18n, Voice, Module Builder, advanced analytics.

5. Risk Register

Technical Risk: Pipeline wiring breaks existing functionality.
Replacing mock runtimes with real ones mid-system may introduce regressions. Mitigation: run full test suite after each runtime wire. Use feature flags to toggle mock vs real. Do one runtime at a time.
Technical Risk: LLM provider latency or outage blocks the AI Copilot.
If the AI provider is slow or down, the Copilot becomes useless. Mitigation: the AI Canon already requires graceful degradation — non-AI features must work when AI is unavailable. Verify this guarantee holds.
Architectural Risk: Entity System (JSONB) query performance at scale.
JSONB queries on `data` fields can be slow with millions of rows. Mitigation: index frequently-queried fields with GIN indexes. Consider extracted columns for high-traffic entity types. Test with 1M entities before launch.
Scalability Risk: Single Postgres instance.
All data in one Postgres instance. Mitigation: connection pooling (PGBouncer), read replicas for analytics queries. Monitor connection counts.
Operational Risk: No CI/CD means manual deploys.
Human error in deployment. Mitigation: Phase 8 builds CI/CD. Until then, script deployment with makefile and verify healthcheck after deploy.
Security Risk: Tenant data isolation bugs.
A bug in tenant-scoped queries could leak data between organizations. Mitigation: integration tests that verify cross-tenant isolation. Hardcoded tenant_id check on every query. Review all SQL queries for tenant scoping before launch.
Deployment Risk: Let's Encrypt certificate expiration.
Auto-renewal already configured in docker-compose. Verify renewal automation works.
Security Risk: `datetime.utcnow()` deprecation (820 warnings).
Cosmetic — no runtime impact. Fix incrementally post-launch.
