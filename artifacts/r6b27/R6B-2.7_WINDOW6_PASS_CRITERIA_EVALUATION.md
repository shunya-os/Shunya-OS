## Additional defect found and fixed during G3 (not in the §15 read taxonomy)

**Denial semantics in the RBAC decorator.** `require_permission` /
`require_any_permission` returned **400 "No organization selected"** whenever the
caller's organization could not be resolved — including when the caller was
simply *not entitled* (no membership at all, or an explicitly selected
organization they do not belong to). An authorization decision presented as a
malformed request hides the denial from the operator and the audit trail, and it
is exactly the ambiguity the directive warns about (authorization denial vs
empty/invalid result).

Fixed with `_resolve_org_or_denial()` in `app/authz/decorators.py`:
- `400` is now reserved for genuinely client-fixable codes
  (`organization_selection_required`, `invalid_requested_organization`);
- `no_active_organization` and `organization_not_authorized` return **403** with
  the canonical `code`, and a `logger.info` AUTHZ DENY line.
- `_resolve_org_id()` is **unchanged** — its ~40 other callers rely on the
  nullable return.

This resolved 5 pre-existing failures (`test_fda16_20`, 4× `test_fda23_people`,
`test_rbac_enforcement`) **without touching any of their assertions**.

**Two fixture gaps (Batch C class), fixed in the fixtures, no assertion relaxed:**
- `tests/test_fda11.py::_setup_auth` — with an explicit `org_id` it never
  provisioned an `OrgMember`, so the (correct) hardened resolver denied. The
  tests mean "an organization with no DATA", not "an identity with no
  membership"; canonical tenancy is now provisioned.
- `tests/test_fda22_admin.py::TestTenantIsolation` — created an `Organization`
  for "Tenant B/C" but no membership, so the tenant user had no tenant context
  and could not receive "its own (empty) list". Canonical tenancy provisioned.
