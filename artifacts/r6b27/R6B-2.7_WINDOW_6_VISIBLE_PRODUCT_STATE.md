## 3. RELEASE-INTEGRITY REMEDIATION (§3) — architecturally fixed

Defect: production served `frontend/dist` from the live checkout, so a local
`npm run build` silently altered production without commit/CI/deploy/cert; and
`deploy.sh` Step 3 hard-reset the worktree **before** any check, destroying
uncommitted work.

Architecture now: source → committed SHA → CI build → **immutable release
artifact** → atomic swap → production.

- `app/frontend_release.py` — resolves the served dir (env override →
  `<releases>/current` when a valid manifest exists → worktree build for dev).
  Self-bootstrapping: no systemd change needed for production to stop serving
  the mutable worktree.
- `app/__init__.py` — serves through the resolver; `/health` reports frontend
  provenance and degrades on frontend/backend SHA drift (drift is now observable).
- `deploy.sh` Step 2b — invokes `deploy_preflight.sh` **before** any reset;
  Step 6b — publishes a per-SHA release + `release.json` and swaps `current`
  with `ln -sfn` + `mv -Tf` (atomic).
- `deploy_preflight.sh` — refuses dirty/untracked trees and mutates nothing.
- `tests/test_release_integrity.py` — 17 tests, including **real execution** of
  the guard against temporary git repos (work survives refusal; untracked files
  are not deleted; the guard contains no mutating git command).

Visible symptom: "Generation failed" / "No canonical workspace context".

**Root cause (evidence-backed):** `app/__init__.py:758` — the global
`before_request` guard denies **every** authenticated request from an identity
with no organization membership:

```

403 {"error": "No organization membership", …}
```

A legitimate user whose only context is a **personal workspace** has no
organization membership → denied. `require_permission` (used by
`/api/v1/ai/chat` for `ai.use`) has the same requirement.

Reproduced in `tests/test_r6b27_output_language.py::test_org_less_identity_is_denied_fail_closed`.

**Why not fixed here:** resolving it requires the canonical personal-workspace
authorization decision — a security-sensitive change to a GLOBAL guard that
affects every route. §6 forbids inventing `org_id`, using `org_id=0`, arbitrary
workspace selection, fabricated membership, legacy fallback or bypassing
authorization. Making that change without the decision would risk weakening
authorization across the product.
