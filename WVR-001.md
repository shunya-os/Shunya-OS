### 4. Were any hidden regressions discovered?

**1 regression discovered:** `use-reality.ts` (in `components/living-workspace/use-reality.ts`) retains its own 15s polling loop to `/api/v1/reality`. This hook was not identified in CDR-006's scope because it is a separate component from `living-store.ts`. The living-store's reality polling was correctly migrated, but the `use-reality.ts` hook — which provides the same reality data — continues polling. This is a duplication of the reality stream: one SSE-based (via living-store bus subscription) and one polling-based (via use-reality.ts).

**Severity:** LOW. The `use-reality.ts` hook is not used by the main living workspace. It is a standalone hook for components that need to subscribe to reality independently. The primary Reality consumer (living-store, via the Living Workspace) is correctly migrated.

### 5. Has repository complexity objectively decreased?

**Yes.** Despite adding 1 file (SSE Runtime), the wave removed 4 files, eliminated 3 duplication sets, unified 2 notification systems, and established a streaming transport for Continuous Reality. The repository is simpler: fewer ownership points, fewer duplicate implementations, fewer polling loops, one canonical event bus.

### 6. Is Wave 1 constitutionally complete?

**No.** One condition prevents closure:

> **The `use-reality.ts` hook retains a 15s Continuous Reality polling loop** that was not identified in CDR-006's architectural scope. This is a duplication of the reality stream: the living-store receives reality via SSE (correct), while `use-reality.ts` continues polling the same endpoint every 15s (incorrect).

**What is required to close Wave 1:**
- Either migrate `use-reality.ts` to use the SSE Runtime (extending CEP-006 scope), or
- Produce a CDR amendment confirming that `use-reality.ts` is a separate architectural concern that should be addressed in a subsequent CEP, or
- Determine that `use-reality.ts` is dead code (no consumers) and remove it entirely.

**Recommendation:** Since `use-reality.ts` is a transport-agnostic hook that already detects `EventSource` support (line 134: `sseSupported: typeof EventSource !== 'undefined'`), the smallest constitutional change is to extend the SSE Runtime to serve as a backend for this hook, replacing its polling with the existing SSE connection. This is a CEP-006 amendment, not a new CEP.
