## Amendments Required Before Genesis

### 1. Constitutional Amendment: Object Type Freeze

**Current state:** The Product Constitution allows new object types to be added by directive.

**Required change:** Add Article: "No new universal concepts shall be added to the ontology. All domain expansion shall occur through ontology composition, relationship patterns, and AI understanding — never through new object types."

**Rationale:** The 18 concepts are proven universal across 20 industries. Adding new concepts would violate the minimality principle and undermine the ontology's universality.

**Constitutional article affected:** Product Constitution, Section on Data Model.

### 2. Constitutional Amendment: Capability Over Module

**Current state:** Features are organized as modules (CRM, Invoicing, Marketing, etc.).

**Required change:** "SHUNYA's architecture shall be organized as capabilities, not modules. Every user-facing feature shall be a composition of capabilities. No capability shall contain domain-specific logic."

**Rationale:** Modules create silos. Capabilities compose. The 18 capabilities catalog provides the universal primitive set.

**Constitutional article affected:** Technical Constitution, Architecture Section.

### 3. Constitutional Amendment: Language Layer Mandate

**Current state:** User interfaces may expose internal concept names (Customer, Invoice, Task).

**Required change:** "No internal concept name shall appear in any user-facing interface. All user-facing terminology shall be determined by the active domain's language. The Human Language Layer is the sole interface between user intent and system operation."

**Rationale:** The founder must never think in SHUNYA object names. The ontology exists for SHUNYA, not for the user.

**Constitutional article affected:** Product Constitution, UX Section.

### 4. Constitutional Amendment: Ontology-Based Storage

**Current state:** Storage uses separate tables and models per object type.

**Required change:** "All records shall be stored using the universal Record abstraction. Primary type determines the concept class. Relationships connect records across types. No storage-level distinction shall exist between a Person, a Commitment, or an Event."

**Rationale:** Separate tables per type prevent cross-domain querying, complicate AI understanding, and require schema changes for every new industry.

**Constitutional article affected:** Technical Constitution, Data Layer Section.

### 5. Constitutional Amendment: Workspace as Composition

**Current state:** Workspaces are hardcoded layouts with predefined panels.

**Required change:** "Every workspace shall be dynamically composed from activated capabilities. No workspace layout shall be hardcoded. Workspace generation shall follow: Intent → Context → Relationships → Memory → Workspace."

**Rationale:** Hardcoded workspaces cannot scale across 20+ industries without creating an explosion of templates. Dynamic composition from capabilities is the only scalable approach.

**Constitutional article affected:** Product Constitution, Workspace Section.

## Amendments Recommended After Genesis

### 6. Decision Ontology Formalization

The Heritage Audit identified the biggest philosophical gap: "What is a decision?" SHUNYA calls itself a Decision Operating System but never defines what a decision is in its ontology.

**Recommendation:** Formalize the Decision concept with:
- Decision lifecycle: Candidate → Evaluated → Decided → Executed → Measured
- Decision quality criteria (what makes a decision good or bad)
- Human vs. system decision authority boundaries
- Decision provenance and audit trail

**Timing:** Post-Genesis, as part of the Intelligence engine.

### 7. Observation Engine

The heritage pipeline starts with Observation. The current SHUNYA has no observation capability — data enters through API calls and user input.

**Recommendation:** Build the Observation engine as a first-class capability. It should perceive system health, user behavior, external signals, and AI inferences.

**Timing:** Post-Genesis, as Observation is the first stage of the SHUNYA pipeline.

### 8. Governance Engine

The heritage architecture defines a Governance engine for policy enforcement. Current governance is embedded in code.

**Recommendation:** Extract governance into a standalone capability that validates architecture rules, compliance policies, and permission boundaries.

**Timing:** Post-Genesis, after core ontology migration.

### 9. Temporal Model

The ontology has no native concept of time beyond Event timestamps. The heritage audit identified this as a gap.

**Recommendation:** Add temporal primitives: urgency, expiry, scheduling, ordering, time-to-decision bounds, temporal logic for workflow conditions.

**Timing:** Post-Genesis, as part of the Workflow capability.
