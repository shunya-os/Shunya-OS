### 8. Every place where another engine would violate single responsibility if it absorbed this engine

| Absorbing Engine | Violation | Evidence |
|-----------------|-----------|----------|
| **Context Fusion (ES-009)** | Identity resolution is a prerequisite for context assembly, not a sub-function of it. Identity has its own state machine (Active → Verified → Superseded \| Merged) that is distinct from context assembly. Identity would overload Context Fusion with lifecycle management on top of pipeline processing. | SHUNYA_CORE_MODELS.md §3 Identity Lifecycle; SUPPORTING_ARCHITECTURE_JUSTIFICATION.md |
| **Knowledge (ES-002)** | Knowledge stores facts immutably. Identity manages a state machine with state transitions (verify, supersede, merge). Knowledge's SHALL NEVER list does not include identity management, but identity lifecycle is not fact storage — it has distinct operational semantics. | ES-002 §SHALL NEVER |
| **Reasoning (ES-003)** | Reasoning would need to manage identity state transitions while also reasoning. Reasoning's SHALL NEVER list explicitly restricts it to reasoning activities. | ES-003 §SHALL NEVER |

**Key constraint:** Identity has a defined state machine, constitutional significance (Invariant 8 — unique identity), and distinct failure modes (ambiguous resolution, unverifiable identity, duplicate merge). It is a prerequisite for Context Fusion, consumed before context assembly begins. Absorbing it into Context Fusion would create a temporal paradox (Context Fusion would need to resolve identity as part of assembling context, but identity resolution is the first step of context assembly — not a component of it).

## Final Determination

**Is each engine already part of Architecture Baseline 1.0?**

### Doctor: YES

- Named as the **Doctor Layer** in SHUNYA_ARCHITECTURE.md §4 (layer diagram) and §5 (layer responsibilities) — the locked constitution
- Defined with full engine specification table in SHUNYA_SYSTEM_FLOW.md §3 (responsibilities, may do, shall never do, events published/consumed, dependencies)
- Referenced by ES-002 (Knowledge Engine) as an event consumer
- Referenced by ARCHITECTURE_BASELINE_REVIEW.md as a recognized engine with a missing specification
- Has a partial implementation (`app/shunya/doctor.py`) proving the concept
- Listed as a valid layer in ENGINE_SPEC_TEMPLATE.md

### Context Fusion: YES

- Defined as a named **stage** in the canonical lifecycle (SHUNYA_SYSTEM_FLOW.md §2) between Knowledge Resolution and Reasoning
- Defined with full engine specification table in SHUNYA_SYSTEM_FLOW.md §3
- Referenced by all 7 pipeline engine specifications (ES-001 through ES-007) as a dependency
- Owned in the Ownership Matrix (ARCHITECTURE_BASELINE_REVIEW.md) — "Context: Context Fusion"
- Validated in the Lifecycle Validation (ARCHITECTURE_BASELINE_REVIEW.md) — step 3: "Knowledge Resolution → Context Fusion: Phase 10 assembles workspace context. ✅"
- Has a computation-only implementation (`app/context/__init__.py`, 334 lines) proving the concept
- Defined in SHUNYA_CORE_MODELS.md §12 Glossary as a canonical term

### Identity: YES

- Defined with full engine specification table in SHUNYA_SYSTEM_FLOW.md §3
- Has a complete canonical model in SHUNYA_CORE_MODELS.md §3 — Identity Model (resolution principles, identity types, state machine, identity object with 10 fields)
- Protected by Architectural Invariant 8 in SHUNYA_CORE_MODELS.md §11 — "Identity is globally unique within a tenant"
- Owned in the Ownership Matrix (ARCHITECTURE_BASELINE_REVIEW.md) — "Tenant identity: Identity Engine"
- Referenced by ES-003 (Reasoning Engine) as a dependency
- Has a full implementation (`app/shunya/identity/__init__.py`, 270 lines) proving the concept
- Defined in SHUNYA_CORE_MODELS.md §12 Glossary as a canonical term
