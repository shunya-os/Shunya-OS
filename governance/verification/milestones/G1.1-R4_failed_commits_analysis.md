## 1. FAILURE CATALOGUE (What Happened)

### Category A: Deleted module orphaned its test files (5 failures)
**Commits:** ffc52de, 9c3d56a  
**SHA span:** 98fed74 → 9c3d56a  
**Root cause:** Deleted `core/execution_runtime/` but didn't delete `tests/execution_runtime/` — CI ran `tests/` and hit `ModuleNotFoundError: No module named 'core.execution_runtime'`  
**Fix:** Removed `tests/execution_runtime/` directory  
**Status:** ✅ RESOLVED

### Category B: Milestone validator expected files not created (6 failures)
**Commits:** 6a67d3d, c0e6b7a, 9ddac63, 88d3a17, d17240e  
**Root cause:** The `validate_milestone.py` script checks for `governance/verification/milestones/{milestone}_evidence.yaml` and `{milestone}_consumers.txt` for EVERY milestone in the tracker. New milestones (G1.1-R4, G1.2, G1.3) needed these files.  
**Fix:** Created all required evidence/consumer files for all milestones  
**Status:** ✅ RESOLVED

### Category C: validate_milestone.py exits 1 on BLOCKED milestones (3 failures)
**Commits:** 6a67d3d, c0e6b7a, 9ddac63  
**Root cause:** `ci_format()` and `main()` exit with code 1 for any non-PASS status. G1.2 and G1.3 are correctly BLOCKED (not started), but validator treats this as CI failure.  
**Fix:** Changed validator to allow BLOCKED as non-failing  
**Status:** ✅ RESOLVED

### Category D: org_members.joined_at NOT NULL constraint (15+ failures across 3 test files)
**Commits:** ffc52de, 20e171f, 067f833, 9d2affe, 98fed74, and earlier  
**Root cause:** Multiple test fixtures (`test_g11_http_identity_security.py`, `test_g11_identity_object.py`, `test_g11_r4_negative.py`) INSERT into `org_members` without `joined_at` which has a NOT NULL constraint at DB level. This is a pre-existing issue that was present in the original G1.1-R2 code.  
**Fix:** Added `joined_at=NOW()` to all fixture INSERTs  
**Status:** ✅ RESOLVED

### Category E: ILIKE is PostgreSQL-specific, breaks on SQLite (10+ failures across 2 test files)
**Commits:** ffc52de, 20e171f, 067f833, 98fed74  
**Root cause:** `core/object_service.py:search()` uses `ILIKE` which is PG-specific. The canonical test suite uses SQLite for CI, so ILIKE throws `OperationalError: near "ILIKE": syntax error`.  
**Fix:** Changed to `LOWER(name) LIKE LOWER(:like)` — portable across all SQL engines  
**Status:** ✅ RESOLVED

### Category F: runtime_count assertion mismatch after removing ExecutionRuntimeAdapter (3 failures)
**Commits:** ffc52de, 20e171f  
**Root cause:** `tests/runtime_pipeline/` had `assert runtime_count == 9` hardcoded. After removing `ExecutionRuntimeAdapter`, the count dropped to 8.  
**Fix:** Updated all assertions to `== 8`  
**Status:** ✅ RESOLVED

### Category G: Pre-existing test infrastructure — SQLite transaction handling (2 failures)
**Commits:** 9d2affe, 5395d45  
**Root cause:** `sqlite3.OperationalError: cannot commit transaction - SQL statements in progress` — SQLite compatibility issue with raw SQL patterns  
**Fix:** `scalar() before commit()` pattern  
**Status:** ✅ RESOLVED

### Category H: Migration idempotency (the original 37f1ecb root cause)
**Commit:** 37f1ecb (user-authored, the last successful deploy before the cascade)  
**Root cause:** Production DB was at a different Alembic branch head than the merge revision. Migration scripts tried to create tables/columns that already existed on production (created via ORM model sync, not migration).  
**Fix:** Added `IF NOT EXISTS` / column-exists checks to migration scripts  
**Status:** ✅ RESOLVED by user

## 2. WHAT MATTERS — Product Improvements We Can Extract

### 2.1. No systematic "clear my data" mechanism for users
**Evidence:** Zero code paths for bulk-deleting user history. `app/media.py` has per-file delete. `app/founder/models.py` has no cascade-purge. No `DELETE FROM founder_conversations WHERE identity_id=?` route exists.  
**Improvement opportunity:** Add a user-facing "Clear all my data" workflow:
- Delete founder conversations + messages
- Delete uploaded media files + records
- Delete founder objects
- Keep identity record (account stays)
- Wrapped in immutable audit log (already exists in `genesis_protection.py`)

### 2.2. No admin data export/backup for user data
**Evidence:** `app/security/encryption.py` exists for Fernet encryption, but only `app/razorpay/routes.py` uses it (payment secrets). There's no "export my data as encrypted archive" for a user.  
**Improvement opportunity:** Add an admin function:
- Export all user data (objects, conversations, media, settings) as JSON
- Encrypt with Fernet using user-derived key
- Store as downloadable `.enc` file or in admin record
- `app/security/encryption.py` already has the primitives — just needs orchestrating

### 2.3. No "media cleanup" GC for orphaned files
**Evidence:** `app/media.py` stores files on disk under `media/YYYY/MM/` but there's no GC for files whose `MediaFile` record was deleted. The `delete()` method handles single files, but orphaned uploads from failed uploads or deleted leads accumulate.  
**Improvement opportunity:** Add a background job or cron:
- Walk `UPLOAD_DIR` for files with no `MediaFile` record
- Walk `media_files` for records with no file on disk → mark as orphaned
- Schedule periodic cleanup via existing cron infrastructure

### 2.4. No "purge founder conversation history" feature
**Evidence:** `app/founder/models.py` has `FounderConversation` and `FounderMessage` but no API route to purge a user's conversation history. The audit system (`genesis_protection.py`) has `DATA_PURGE` action but no consumer.  
**Improvement opportunity:** Add:
- `POST /api/founder/purge-conversations` — deletes all conversations for this identity
- Records in immutable audit log with `AuditAction.DATA_PURGE`

### 2.5. Test infrastructure is fragile between SQLite and PostgreSQL
**Evidence:** 15+ CI failures from `ILIKE` (PG-only) and `org_members.joined_at` (SQLite enforces NOT NULL differently). The CI runs tests on SQLite, but production is PostgreSQL. Every raw SQL statement in production code is a potential CI failure.  
**Improvement opportunity:** Either:
- (a) Use PostgreSQL for CI (mirrors production)
- (b) Add a CI test mode that runs tests against both engines
- (c) Create a SQL compatibility lint rule that catches `ILIKE` and other PG-isms

### 2.6. No migration state verification before deploy
**Evidence:** 37f1ecb root cause: production DB had columns created by ORM sync, not by migration. Alembic walked the other branch and tried to create them again.  
**Improvement opportunity:** Add a pre-deploy check:
- Compare `alembic current` against expected head
- Check for column/table existence before `upgrade`
- Fail deploy with clear message if mismatch

### 2.7. Milestone validator is a good pattern, needs broader adoption
**Evidence:** The validator caught every missing evidence file, every consumer audit gap, every tracker inconsistency. It's a systematic quality gate that works.  
**Improvement opportunity:** Expand validator to check:
- All production routes have at least one test
- No raw SQL without SQLite compat review
- All `register_execution_actions()` methods are removed before merge
