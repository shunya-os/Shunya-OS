# G1.1-R6B Object Convergence — Migration Plan

## Canonical Architecture Target

```
Production code path
    ↓
ObjectService.create() / .update() / .delete()
    ↓
sh_objects (sole canonical table)
```

## 7 Production Write Sites — Migration Steps

### Site 1: `app/upload/routes.py:54-76` — raw SQL INSERT
**Status: MIGRATED (proven pattern)**

Replaced `INSERT INTO founder_objects` + `INSERT INTO sh_objects` with `ObjectService.create()`. 
Requires `organization_id` — resolved via OrgMember lookup by identity_id.
Dual-write eliminated. Single canonical write path.

## Read Site Migration Strategy

50+ production read sites reference `founder_objects`. Strategy:
1. Route new reads to `sh_objects` via `get_canonical_object()` in `app/objects/canonical.py`
2. Remove `founder_objects` fallback from `get_canonical_object()` once writes are zero
3. Migrate each raw SQL `FROM founder_objects` to `FROM sh_objects`
4. Prove no production code path touches founder_objects after migration

3. grep for remaining founder_objects references
4. Classify every remaining reference as MIGRATED, LEGACY-COMPAT, or BLOCKER
