## 2. Organization mismatches (288 objects)

### Evidence
Both object.organization_id and workspace.organization_id are set, but disagree.

### Distribution
- 151 with object.org > workspace.org (e.g. object.org=901, workspace.org=7)
- 137 with object.org < workspace.org (e.g. object.org=1, workspace.org=7)

### Root cause
All mismatches involve the `spc_business` workspace. The object.org was set incorrectly
during earlier convergence runs that either:
- Used `organization_id=1` as default fallback (the G1.1-R1 era org=1 fallback pattern)
- Used `organization_id=901` from an ephemeral test/CI database

The CORRECT org is 7 — the workspace's owning organization.

### Classification
**SAFE_REMAP_WITH_EVIDENCE** — mismatch resolved by workspace ownership precedence.

### Remap SQL (verified, NOT executed — for reference):
```sql
UPDATE sh_objects s SET organization_id = w.organization_id
FROM sh_workspaces w
WHERE s.organization_id IS NOT NULL
AND w.id = s.workspace_id
AND w.organization_id IS NOT NULL
AND s.organization_id <> w.organization_id;
```
