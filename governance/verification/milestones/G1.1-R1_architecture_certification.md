## REAL JOURNEY TRACED: Object Creation via HTTP

```
Login (/auth/login)
  → app/auth_routes.py (login route, sets session)
  → app/__init__.py before_request middleware (sets g.identity_id, session.current_org_id)
  → client POST /api/v1/objects/ {"name": "Test", "object_type": "document"}
  → app/objects/routes.py create()
    → _resolve_tenant_id() from session.current_org_id
    → ShunyaObject() — legacy ORM, NO organization_id column, writes to sh_objects
    → Object() — legacy model, writes to objects table
    → db.session.commit()
  → Returns 200 {success: true}
```

**CRITICAL FINDING:** The canonical `core/object_service.py` was never called. The object was written to `sh_objects` WITHOUT `organization_id` in the column (stored only in JSON `data`). The `organization_id` FK constraint may fail on new objects if the migration set it NOT NULL (the migration shows `nullable=True`, so it accepts NULL silently).

**VERDICT:** REAL JOURNEY: FAIL — the supposed canonical path is bypassed at every step.

## GREEN-BUT-NOT-CANONICAL FINDINGS

2. **All `test_g11_identity_object.py` tests**: All pass, but they test `core.object_service.get_object_service()` directly — never via the HTTP route. The HTTP route does NOT use this service. The tests prove the service works in isolation but prove nothing about the actual production path.

3. **Milestone validator**: Passes all mechanical gates (evidence file exists, config found, git state clean, etc.) but cannot detect the architectural bypass of `core/object_service.py` by the HTTP route. Mechanical validation is insufficient for architectural truth.

4. **`test_cross_tenant_search_excludes`**: Uses `core.object_service` directly with controlled `organization_id` — but real objects created via HTTP don't have `organization_id` set, so tenant isolation via this column is unenforced for HTTP-created objects.

5. **"tests/ test_g11_identity_object.py 58 passed"**: The 58 tests prove unit-level correctness of isolated services. They do NOT prove architectural convergence.

## REMEDIATION REQUIRED

### CRITICAL (blocking certification)

1. **Fix `ShunyaObject` ORM model to include `organization_id` column** — or migrate the HTTP route to use `core/object_service.py` directly. Currently every object created via HTTP bypasses the canonical service AND has NULL organization_id.

2. **Fix `app/objects/routes.py` create() to call `core.object_service.get_object_service().create()`** instead of dual-writing to two ORM models.

3. **Strengthen `test_create_via_http` to verify persisted DB state** — check that `organization_id` column is populated and FK is valid.

### HIGH

4. **Remove or quarantine competing identity modules** — `app/production/identity_repository.py`, `core/identity_engine.py`, `core/identity_interface.py` must be explicitly classified and either converted to adapters or archived.

5. **Fix `IdentityResolutionService` fallback** — `team_members.tenant_id` fallback (line 132) silently maps users to wrong org. Should return None and force explicit resolution.

6. **Consolidate KnowledgeDocument into DocumentRecord** — 3 active production callers still use the legacy KnowledgeDocument model.

### MEDIUM

7. **Wire or archive orphan runtimes** — `core/planning_runtime/`, `core/execution_runtime/`, `core/cognitive_runtime/`, `core/workspace_runtime/`, `core/memory_knowledge_runtime/` must have a documented classification — not just "orphan" status.

8. **Wire UCP-05 (decision) and UCP-06 (agreement)** into their respective production pipelines, or document why they remain standalone.

**OVERALL: NOT CERTIFIED**

G1.1-R1 fails architectural certification because the primary production path for object creation — the HTTP API — bypasses the canonical `ObjectService` and writes objects with NULL `organization_id`. The test suite proves service-level correctness in isolation but does not test the actual production wire path. Three competing identity resolution paths remain importable.

**Minimum remediation for certification:**

1. Fix the HTTP object create route to call `core/object_service.py`
2. Add `organization_id` to `ShunyaObject` ORM model
3. Strengthen HTTP test to verify persisted DB state including organization_id
4. Classify or quarantine competing identity modules

**Do not begin G1.2 until certification gates are addressed.**
