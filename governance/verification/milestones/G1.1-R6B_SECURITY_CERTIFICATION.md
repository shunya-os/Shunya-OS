# G1.1-R6B Security Certification

## Status: OPEN — NOT CERTIFIED

## CSRF (§14 of Directive 03)

**Evidence:** `app/security/csrf.py` implements SameSite=Strict cookies + JSON content-type enforcement. Flask-WTF CSRFProtect is loaded but API surface is exempt (standard practice for JSON API + SPA architecture).

**Assessment:** Appropriate for an SPA+JSON-API application. Cross-site form-based CSRF is blocked by SameSite=Strict + JSON content type requirement (browsers cannot set `Content-Type: application/json` via cross-site form POST). CSRFProtect is available for any future form-based flows.

**Status: PASS (existing)**

## PDFKit / HTML Rendering Security (§13 of Directive 03)

**Vulnerability found:** `app/pdf_safe.py:generate_pdf()` applied caller `extra_options` AFTER security defaults using `options.update(extra_options)`, allowing callers to re-enable JavaScript.

**Fix applied:** Security invariants (`no-javascript`, `disable-javascript`, `javascript-delay`, `no-stop-slow-scripts`) are now enforced AFTER caller options via `options.update(SECURITY_INVARIANTS)`. Caller flexibility cannot override security invariants.

**Negative test:** Not yet added. Required per directive.

**Status: FIXED (product change) — needs negative test**

## Test Isolation (§5 of Directive 03)

**Fail-closed invariant:** Added to `app/__init__.py` in `create_app()`. When `TESTING=True`, if the database URI matches the production pattern (`shunya` + `localhost:5432`), `RuntimeError` is raised.

**Verified:**
- TESTING + sqlite:///:memory: → PASS
- TESTING + production URL → RuntimeError (PASS)
- no TESTING + production URL → no check (PASS)

**Status: PARTIAL — remaining dangerous test files fixed, invariant proven
