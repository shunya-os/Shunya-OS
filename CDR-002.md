Remove `components/copilot/ai-copilot.tsx`. No other changes.

- + Zero consumer impact (verified — no imports)

- − REJECTED: violates Simplicity Rule §4 (would re-add abstraction)

Retain `ai-copilot.tsx` with a deprecation warning.

**Trade-offs:**
- − Violates Canonical Ownership Law §10 (two owners remain)
- − Keeps dead code in the repository
- − REJECTED: directly contradicts the constitutional objective

Rewrite `ai-copilot.tsx` to re-export from canonical panel.

**Trade-offs:**
- − Introduces a compatibility layer (forbidden by CEP approval: "no temporary compatibility layer")
- − REJECTED: violates the implementation authorization

**Justification:**
1. Zero consumers — verified by static analysis

3. Canonical panel fully functional — no founder capability lost

## Wave 1 Discovery Findings (CEP-003 & CEP-006)

These findings are documented for Wave 1 planning. **They do not expand CEP-002 implementation scope.**

### Finding 1 — CEP-003 (Event Bus): legacy event bus consumers identified

`api/event-bus.ts` (the legacy event bus CEP-003 will eliminate) has these consumers:

| Consumer | File |
|----------|------|
| `use-ai-presence` | `api/use-ai-presence.ts` |
| `use-realtime-sync` | `api/use-realtime-sync.ts` |
| `use-query` | `api/use-query.ts` |
| orchestrator | `runtimes/orchestrator.ts` |
| registration | `runtimes/registration.ts` |
| state-fabric | `runtimes/state-fabric.ts` |

**Implication for CEP-003:** The Wave 1 Event Bus consolidation must migrate all 6 consumers to `runtimes/event-bus.ts`. Notably, `use-ai-presence.ts` and `use-realtime-sync.ts` are the exact hooks CEP-006 will also touch — so CEP-003 and CEP-006 **share migration surface**. Executing CEP-003 before CEP-006 ensures these hooks are already on the canonical bus when SSE replaces their polling.

### Finding 2 — CEP-006 (SSE): dual polling of AI insights endpoint

Two independent pollers hit `/api/v1/ai/insights`:

| Poller | File | Interval |
|--------|------|----------|
| Living Store | `living-store.ts` | 15s (REALITY_POLL_MS) |
| AI Presence hook | `use-ai-presence.ts` | 45s (POLL_INTERVAL_MS) |

**Implication for CEP-006:** The canonical `ai-presence-panel` reads from `living-store` (15s), not from `use-ai-presence` (45s). CEP-006 should consolidate these into a single SSE stream. The canonical panel's data path is `living-store` → SSE; the legacy `use-ai-presence` hook's 45s poll is redundant and should be retired.

### Finding 3 — CEP-006 (SSE): no backend SSE endpoint yet

- Backend `ai_bp` currently exposes only `/chat` (no `/insights` SSE)
- `/api/v1/ai/insights` is a polling endpoint (JSON)
- `use-realtime-sync.ts` polls `/api/v1/events` on 15s

**Implication for CEP-006:** Requires a new SSE endpoint on the backend (e.g. `/api/v1/events/stream` or `/api/v1/ai/insights/stream`). This is a backend + frontend Wave 1 effort.

### Wave 1 Dependency Graph (coherent Living OS Runtime)

```
CEP-003 (Event Bus)                     CEP-006 (SSE)
  migrate 6 consumers from                replace polling with SSE:
  api/event-bus.ts → runtimes/            - living-store (15s) → SSE
  event-bus.ts                             - use-ai-presence (45s) → SSE
    └─ use-ai-presence                     - use-realtime-sync (15s) → SSE
    └─ use-realtime-sync                    └─ backend: new SSE endpoint
    └─ use-query
    └─ orchestrator / registration /
       state-fabric

CEP-002 (AI Presence) — DONE first:
  removes dead ai-copilot.tsx
  canonical ai-presence-panel reads living-store
  → cleanly positioned for CEP-006 SSE
```

**Recommended Wave 1 execution order:** CEP-002 (done) → CEP-003 (Event Bus — migrates hooks to canonical bus) → CEP-006 (SSE — replaces polling those hooks).
