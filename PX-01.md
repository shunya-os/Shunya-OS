## 3. Arrival Journey Blueprint

```
┌─────────────────────────────────────────────────────────┐
│                    ARRIVAL JOURNEY                       │
├─────────────────────────────────────────────────────────┤
│                                                         │

│      ↓             ↓               ↓           ↓        │
│  SHUNYA is      "Here are      "Here is     "I            │
│  thinking       your things"   what was     trust this"  │
│                                 done"                    │

│  Invitation ──→ Authentication ──→ Same Workspace       │
│      ↓               ↓                  ↓               │

```

### Scene Breakdown

**Scene 1: Silence** — The visitor arrives at `/`. Dark, calm, minimal. A single word or symbol. No navigation, no buttons, no paragraphs. Duration: 1–2 seconds of intentional silence.

**Scene 2: One Thought** — A thought appears. Example: "Your business has 47 objects that need attention." Or: "Three people tried to reach you today." The thought is real SHUNYA data (demonstration mode). This is the first communication.

**Scene 3: Reality** — The Reality Stream gently fades in. Events appear one at a time: "Invoice INV-003 was created." "Proposal for GlobalTech was reviewed." "Task 'Call Acme' was completed." The visitor sees SHUNYA's reality unfolding.

**Scene 4: Attention** — The Attention Queue highlights items that matter. The system explains why each item matters: "This invoice is overdue by 5 days." "This proposal has a 92% win probability." Trust is demonstrated through evidence.

**Scene 5: AI Begins Thinking** — The AI Presence panel appears. SHUNYA shows its observation process: "I noticed that INV-003 is overdue. I checked payment history. I drafted a reminder." The visitor sees intelligence, not just results.

**Scene 6: Living Objects** — Living Objects emerge. Each object has a name, status, relationships, and timeline. The visitor can see how objects connect: "Invoice INV-003 relates to Customer Acme Corp and Proposal PROP-002."

**Scene 7: Execution** — SHUNYA demonstrates execution. A commitment is created, tracked, and completed. The visitor sees causality: observation → decision → action → outcome.

**Scene 8: Trust** — The visitor can inspect any claim. Click on "Invoice INV-003 is overdue" → see the evidence chain: payment date, invoice date, communication history, payment terms. Trust is demonstrated through transparency.

**Scene 9: Invitation** — "Would you like to own this?" A gentle invitation to create an account. No urgency. No pressure. The visitor already understands SHUNYA.

**Scene 10: Authentication** — Identity is established. The same workspace continues — no reload, no transition. The demonstration data is replaced by the visitor's real data.

**Scene 11: My Reality** — The authenticated Living Workspace. The visitor feels: "Nothing changed except this is now mine."

## 4. Workspace Continuity Blueprint

| Dimension | Before Auth | After Auth | Continuity Mechanism |
|-----------|-------------|------------|---------------------|
| Layout | Arrival layout | Living Workspace layout | Same shell component. Identity changes data source, not structure. |
| Visual language | Living Workspace design tokens | Same tokens | Single token system. No theme switch. |
| Reality Stream | Demo reality | Live reality | Same Reality Stream component. Data source switches from demo to live. |
| Living Objects | Demo objects | Real objects | Same Object Runtime. Objects are data — identity changes the tenant. |
| AI Presence | Demo AI | Live AI | Same AI Presence Runtime. AI context switches from demo to user. |
| Trust | Demonstrates trust | Proves trust | Same evidence chain mechanism. |
| Navigation | No navigation | Living Workspace navigation | Navigation enters when the visitor owns the workspace. |

**Key principle:** The shell does not change. The data changes. Authentication is a data-layer event, not a UI-layer event.

## 5. Motion & Interaction Storyboard

### Principles
- Every animation must teach. Never decorate.
- Motion is the language of causality — show cause before effect.
- Transitions are continuous: no cut, no fade-to-black, no loading spinner.
- Timing follows the pace of understanding, not the pace of technology.

### Storyboard

| Frame | Motion | What it teaches | Timing |
|-------|--------|-----------------|--------|
| Silence | Static. Maybe a gentle pulse. | "This is a living system. It is waiting." | 2s |
| Thought appears | Fade in + gentle upward drift. | "Something is emerging." | 1.5s |
| Reality events | Each event slides in from below, then settles. | "Events happen continuously. They arrive." | 3s per event |
| Attention shift | Items pulse gently. Priority items glow. | "Some things matter more than others." | Continuous |
| AI thinking | A subtle ripple or expansion. | "Understanding is forming." | 2s per observation |
| Living Objects | Objects bloom from relationships. | "Things are connected." | 1s per object |
| Execution | A commitment line progresses from left to right. | "Actions complete over time." | 4s per execution |
| Trust reveal | Clicking an item expands an evidence chain. | "Every claim has support." | User-paced |
| Invitation | Gentle scale-up of the CTA. | "The door is open." | 1s |
| Auth transition | No animation. Data changes silently. | "Identity is infrastructure." | Instant |

## 6. Trust Demonstration Plan

### Trust Layer Architecture

Every claim made by SHUNYA in the public experience shall be backed by an evidence chain accessible through a single click.

```
Claim: "Invoice INV-003 is overdue by 5 days."
  ↓ Click
Evidence Chain:
  ┌─────────────────────────────────────┐
  │ Invoice INV-003                     │
  │ Created: 2026-07-28                 │
  │ Due date: 2026-07-31                │
  │ Amount: $4,200                      │
  │ Status: unpaid                      │
  │ Customer: Acme Corp                │
  ├─────────────────────────────────────┤
  │ Observation: Due date passed        │
  │ Observed: 2026-08-01 at 00:00:00    │
  │ Confidence: 1.0 (computed)          │
  ├─────────────────────────────────────┤
  │ Current date: 2026-08-05            │
  │ Days overdue: 5                     │
  │ Calculated: 2026-08-05 - 2026-07-31 │
  └─────────────────────────────────────┘
```

### Trust by Demonstration

| Trust Signal | How it's demonstrated | Evidence |
|--------------|----------------------|----------|
| SHUNYA observes reality | Reality Stream shows events as they occur | Each event has a timestamp |
| SHUNYA understands causality | Attention queue shows why items matter | Each attention item has a reasoning chain |
| SHUNYA is intelligent | AI Presence shows its observation process | Each observation has a confidence score |
| SHUNYA is transparent | Every claim is clickable to its evidence chain | Evidence chain is the UI |
| SHUNYA remembers | Timeline shows object history | Each object has an append-only timeline |
| SHUNYA executes | Commitments appear and complete | Each commitment has a lifecycle |
| SHUNYA is trustworthy | No hidden claims — everything is verifiable | Evidence chain is always accessible |

### Anti-Patterns (Forbidden)

- Testimonials ("Trusted by 10,000+ businesses")
- Trust badges ("SOC 2, GDPR compliant")
- Marketing claims ("AI-powered, intelligent")
- Social proof ("Join 5,000+ happy customers")
- Certifications displayed as decoration

Trust is demonstrated through the product. Never claimed through marketing.

## 7. Information Architecture

```
/ (Arrival)
├── Silence (Scene 1)
├── Thought (Scene 2)
├── Reality (Scene 3)
├── Attention (Scene 4)
├── AI Thinking (Scene 5)
├── Living Objects (Scene 6)
├── Execution (Scene 7)
├── Trust (Scene 8)
├── Invitation (Scene 9)
├── Authentication (Scene 10)
│
└── Dashboard (My Reality / Living Workspace)
    ├── Reality Stream
    ├── AI Presence
    ├── Executive Briefing
    ├── Living Objects
    ├── Command Surface
    └── Living Store
```

**Key architecture decisions:**
- Single page — no URL routing changes during the arrival journey
- All scenes are stages of a single component, not separate pages
- The Living Workspace component is the same component before and after auth
- `/living` redirects to `/` (the arrival experience is the canonical entry)

## 8. Responsive Behaviour Plan

| Breakpoint | Behaviour | Rationale |
|------------|-----------|-----------|
| >1200px | Full Living Workspace layout. 3-column: Reality | AI | Objects | The canonical experience |
| 768–1200px | 2-column layout. Reality + AI stacked, Objects below | Maintains continuous awareness |
| <768px | Single-column, vertical flow. Reality → AI → Objects | Stacked for mobile, preserves order of importance |
| <480px | Minimal. Reality Stream only. Objects and AI accessible via expand | Focus on what matters most |

**Key principle:** The arrival experience is never "mobile-first" — it is "awareness-first." The layout adapts to preserve the experience hierarchy, not the screen size.

## 10. Product Experience Review

### Experience Constraints

- The arrival experience must be built using the same production components, runtimes, Living Objects, Attention, Cognition, Reality, and Workspace infrastructure as the authenticated product.
- It shall never become a separate marketing application.
- Any capability demonstrated publicly must be the real SHUNYA capability operating on demonstration data, not a simulation built solely for the homepage.
- This keeps the homepage and the product from drifting apart over time, ensuring every improvement benefits both experiences simultaneously.

### Experience Verification

Before implementation, confirm:

- [ ] Every component used in the arrival experience is a production component from the Living Workspace
- [ ] Every runtime used is the canonical runtime (SSE Runtime, Event Bus, Reality Engine)
- [ ] Every data point shown is either real (user's data) or demonstration data flowing through the same pipeline
- [ ] No component is built specifically for the homepage that duplicates a production component
- [ ] The arrival experience is a state of the Living Workspace, not a separate application
- [ ] Authentication changes the data source, not the application shell

### Constitutional Compliance

| Principle | Compliance |
|-----------|-----------|
| **Article II — Reality** | Demonstrated through real Reality Stream events |
| **Article V §5.5 — Event Architecture** | All events flow through the canonical event bus |
| **Article V §5.3 — Engine Architecture** | AI Presence, Reality Engine, Object Runtime all canonical |
| **§2.4 — Timeline Primacy** | Every event has a timestamp and evidence chain |
| **§2.5 — Observation and Fallibility** | AI observations carry confidence scores |
| **§5.2 — Layer Architecture** | Experience layer imports from all layers below |
| **§6.2 — No-Duplication** | No component duplicated between public and authenticated experiences |
